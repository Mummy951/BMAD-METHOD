# 清单验证任务

本任务提供根据清单验证文档的说明。代理“必须”遵循这些说明，以确保对文档进行彻底和系统的验证。

## 可用清单

如果用户询问或未指定特定清单，请列出代理角色可用的清单。如果任务不是由特定代理运行，请告知用户检查 `.bmad-core/checklists` 文件夹以选择要运行的相应清单。

## 说明

1. **初步评估**
   - 如果用户或正在运行的任务提供清单名称：
     - 尝试模糊匹配（例如，“架构清单”->“architect-checklist”）
     - 如果找到多个匹配项，请用户澄清
     - 从 `.bmad-core/checklists/` 加载相应的清单
   - 如果未指定清单：
     - 询问用户要使用哪个清单
     - 呈现清单文件夹中文件的可用选项
   - 确认他们是否要完成清单：
     - 逐节（交互模式 - 非常耗时）
     - 一次性（YOLO 模式 - 建议用于清单，最后会有部分摘要供讨论）

2. **文档和工件收集**
   - 每个清单都将在开头指定其所需的文档/工件
   - 遵循清单的特定说明以收集内容，通常可以在 docs 文件夹中解析文件，如果不能或不确定，请暂停并询问或与用户确认。

3. **清单处理**

   如果在交互模式下：
   - 逐个处理清单的每个部分
   - 对于每个部分：
     - 按照清单中嵌入的该部分的说明审查该部分中的所有项目
     - 根据相关文档或工件检查每个项目
     - 呈现该部分的发现摘要，突出显示警告、错误和不适用项目（不适用理由）。
     - 在继续下一部分之前获得用户确认，或者如果有什么重大问题，我们是否需要暂停并采取纠正措施

   如果在 YOLO 模式下：
   - 一次性处理所有部分
   - 创建包含所有发现的综合报告
   - 向用户呈现完整的分析

4. **验证方法**

   对于每个清单项目：
   - 阅读并理解要求
   - 在文档中查找满足要求的证据
   - 考虑显式提及和隐式覆盖
   - 除此之外，遵循所有清单 llm 说明
   - 将项目标记为：
     - ✅ PASS：要求明确满足
     - ❌ FAIL：要求未满足或覆盖不足
     - ⚠️ PARTIAL：某些方面已覆盖但需要改进
     - N/A：不适用于此案例

5. **部分分析**

   对于每个部分：
   - 逐步思考以计算通过率
   - 识别失败项目中的共同主题
   - 提供具体的改进建议
   - 在交互模式下，与用户讨论发现
   - 记录任何用户决定或解释

6. **最终报告**

   准备一份摘要，其中包括：
   - 清单整体完成状态
   - 按部分的通过率
   - 失败项目列表及其上下文
   - 具体的改进建议
   - 任何标记为 N/A 的部分或项目以及理由

## 清单执行方法

每个清单现在都包含嵌入式 LLM 提示和说明，它们将：

1. **指导深入思考** - 提示确保对每个部分的深入分析
2. **请求特定工件** - 关于需要哪些文档/访问权限的清晰说明
3. **提供上下文指导** - 特定于部分的提示，以实现更好的验证
4. **生成综合报告** - 包含详细发现的最终摘要

LLM 将：

- 执行完整的清单验证
- 呈现包含通过/失败率和关键发现的最终报告
- 提供对任何部分的详细分析，特别是那些带有警告或失败的部分
