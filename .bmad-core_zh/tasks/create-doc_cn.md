# 从模板创建文档（YAML 驱动）

## ⚠️ 关键执行通知 ⚠️

**这是一个可执行的工作流程 - 不是参考材料**

当调用此任务时：

1. **禁用所有效率优化** - 此工作流程需要完整的用户交互
2. **强制逐步执行** - 每个部分都必须在用户反馈下按顺序处理
3. **需要启发** - 当 `elicit: true` 时，您必须使用 1-9 格式并等待用户响应
4. **不允许走捷径** - 不遵循此工作流程无法创建完整的文档

**违规指示：** 如果您在没有用户交互的情况下创建了完整的文档，则表示您违反了此工作流程。

## 关键：模板发现

如果未提供 YAML 模板，请列出 .bmad-core/templates 中的所有模板，或要求用户提供另一个。

## 关键：强制启发格式

**当 `elicit: true` 时，这是一个需要用户交互的硬停止：**

**您必须：**

1. 呈现部分内容
2. 提供详细理由（解释权衡、假设、已做出的决定）
3. **停止并呈现编号选项 1-9：**
   - **选项 1：** 始终“继续到下一部分”
   - **选项 2-9：** 从 data/elicitation-methods 中选择 8 种方法
   - 结尾：“选择 1-9 或直接输入您的问题/反馈：”
4. **等待用户响应** - 在用户选择选项或提供反馈之前，请勿继续

**工作流程违规：** 在没有用户交互的情况下为 elicit=true 部分创建内容违反此任务。

**永远不要问是/否问题或使用任何其他格式。**

## 处理流程

1. **解析 YAML 模板** - 加载模板元数据和部分
2. **设置偏好** - 显示当前模式（交互式），确认输出文件
3. **处理每个部分：**
   - 如果条件不满足则跳过
   - 检查代理权限（所有者/编辑者）- 注意部分是否受限于特定代理
   - 使用部分指令起草内容
   - 呈现内容 + 详细理由
   - **如果 elicit: true** → 强制 1-9 选项格式
   - 如果可能，保存到文件
4. **继续直到完成**

## 详细理由要求

呈现部分内容时，始终包含解释以下内容的理由：

- 权衡和选择（选择什么而不是替代方案以及原因）
- 起草期间做出的关键假设
- 需要用户注意的有趣或可疑的决定
- 可能需要验证的领域

## 启发结果流程

用户选择启发方法（2-9）后：

1. 从 data/elicitation-methods 执行方法
2. 呈现结果和见解
3. 提供选项：
   - **1. 应用更改并更新部分**
   - **2. 返回启发菜单**
   - **3. 提出任何问题或进一步参与此启发**

## 代理权限

处理具有代理权限字段的部分时：

- **所有者**：注意哪个代理角色最初创建/填充该部分
- **编辑者**：列出允许修改该部分的代理角色
- **只读**：标记创建后无法修改的部分

**对于受限访问的部分：**

- 在生成的文档中包含一条注释，指示负责的代理
- 示例：“_（本部分由开发代理拥有，只能由开发代理修改）_”

## YOLO 模式

用户可以输入 `#yolo` 以切换到 YOLO 模式（一次处理所有部分）。

## 关键提醒

**❌ 永远不要：**

- 提出是/否问题进行启发
- 使用除 1-9 编号选项之外的任何格式
- 创建新的启发方法

**✅ 始终：**

- 当 elicit: true 时，使用精确的 1-9 格式
- 仅从 data/elicitation-methods 中选择选项 2-9
- 提供解释决策的详细理由
- 结尾是“选择 1-9 或直接输入您的问题/反馈：”
