# 架构师解决方案验证清单

此清单作为架构师在开发执行前验证技术设计和架构的综合框架。架构师应系统地检查每个项目，确保架构健壮、可扩展、安全，并与产品需求保持一致。

[[LLM: 初始化说明 - 所需工件

在进行此清单之前，请确保您能够访问：

1. architecture.md - 主要架构文档（检查 docs/architecture.md）
2. prd.md - 用于需求对齐的产品需求文档（检查 docs/prd.md）
3. frontend-architecture.md 或 fe-architecture.md - 如果是 UI 项目（检查 docs/frontend-architecture.md）
4. 架构中引用的任何系统图
5. 可用的 API 文档
6. 技术栈细节和版本规范

重要提示：如果任何所需文档缺失或无法访问，请立即向用户询问其位置或内容，然后继续。

项目类型检测：
首先，通过检查以下内容确定项目类型：

- 架构是否包含前端/UI 组件？
- 是否有 frontend-architecture.md 文档？
- PRD 是否提及用户界面或前端需求？

如果这是仅后端或仅服务的项目：

- 跳过标有 [[FRONTEND ONLY]] 的部分
- 额外关注 API 设计、服务架构和集成模式
- 在最终报告中注明由于项目类型而跳过的所有前端部分

验证方法：
对于每个部分，您必须：

1. 深度分析 - 不要只勾选框，要根据提供的文档彻底分析每个项目
2. 基于证据 - 在验证时引用文档中的特定部分或引文
3. 批判性思维 - 质疑假设并发现差距，而不仅仅是确认存在的内容
4. 风险评估 - 考虑每个架构决策可能出现的问题

执行模式：
询问用户是否要通过清单：

- 逐节（交互模式） - 审查每个部分，提交发现，在继续之前获得确认
- 一次性（综合模式） - 完成全面分析并在结束时提交综合报告]]
