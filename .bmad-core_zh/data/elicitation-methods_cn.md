# 启发方法数据

## 核心反思方法

**为受众扩展或收缩**

- 询问是“扩展”（添加细节、阐述）还是“收缩”（简化、澄清）
- 识别相关的特定目标受众
- 相应地调整内容的复杂性和深度

**解释推理（CoT 逐步）**

- 逐步展示思考过程
- 揭示潜在假设和决策点
- 展示如何从当前角色的角度得出结论

**批判和完善**

- 审查输出中的缺陷、不一致或改进领域
- 从角色的专业知识中识别特定弱点
- 建议反映领域知识的完善版本

## 结构分析方法

**分析逻辑流和依赖关系**

- 检查内容结构的逻辑进展
- 检查内部一致性和连贯性
- 识别和验证元素之间的依赖关系
- 确认有效的排序和顺序

**评估与总体目标的对齐**

- 评估内容对已声明目标的贡献
- 识别任何未对齐或差距
- 从特定角色的角度解释对齐
- 建议调整以更好地服务目标

## 风险和挑战方法

**识别潜在风险和意外问题**

- 从角色的专业知识中进行潜在风险的头脑风暴
- 识别被忽视的边缘情况或场景
- 预测意想不到的后果
- 强调实施挑战

**从批判性角度挑战**

- 对当前内容采取批判性立场
- 从指定观点扮演魔鬼代言人
- 反驳突出弱点的提案
- 适当时应用YAGNI原则（范围裁剪）

## 创造性探索方法

**思维树深入探究**

- 将问题分解为离散的“思想”或中间步骤
- 同时探索多个推理路径
- 使用自我评估将每个路径分类为“确定”、“可能”或“不可能”
- 应用搜索算法（BFS/DFS）寻找最佳解决方案路径

**事后诸葛亮：'如果……就好了'的反思**

- 基于当前内容想象回顾性场景
- 识别“如果我们当时知道/做了X……”的洞察
- 幽默或戏剧性地描述想象的后果
- 为当前上下文提取可操作的学习

## 多角色协作方法

**敏捷团队视角转换**

- 轮流查看不同的Scrum团队成员观点
- 产品负责人：关注用户价值和业务影响
- Scrum Master：检查流程和团队动态
- 开发人员：评估技术实施和复杂性
- QA：识别测试场景和质量问题

**利益相关者圆桌会议**

- 召集多个角色的虚拟会议
- 每个角色对内容贡献独特视角
- 识别观点之间的冲突和协同效应
- 将洞察综合为可操作的建议

**元提示分析**

- 退一步分析当前方法的结构和逻辑
- 质疑正在使用的格式和方法
- 建议替代框架或心智模型
- 优化启发过程本身

## 2025年高级技术

**自洽性验证**

- 为相同问题生成多个推理路径
- 比较不同方法之间的一致性
- 识别最可靠和最稳健的解决方案
- 突出方法分歧的区域及原因

**ReWOO（无观察推理）**

- 将参数推理与基于工具的操作分离
- 在没有外部依赖的情况下创建推理计划
- 识别可以通过纯推理解决的问题
- 优化效率并减少token使用

**角色-模式混合**

- 将特定角色专业知识与启发模式相结合
- 架构师+风险分析：深入的技术风险评估
- UX专家+用户旅程：端到端体验批判
- 产品经理+利益相关者分析：多视角影响审查

**新兴协作发现**

- 允许多个视角自然出现
- 从角色互动中识别意想不到的洞察
- 探索观点的新颖组合
- 从多代理思维中捕获意外发现

## 基于游戏的启发方法

**红队与蓝队**

- 红队：攻击提案，发现漏洞
- 蓝队：防御和加强方法
- 竞争性分析揭示盲点
- 产生更健壮、经得起考验的解决方案

**创新锦标赛**

- 让多个替代方法相互竞争
- 根据不同标准对每个方法进行评分
- 从不同角色众包评估
- 识别功能获胜组合

**密室逃脱挑战**

- 将内容作为工作约束
- 在严格限制内找到创意解决方案
- 识别最小可行方法
- 发现创新的变通方法和优化

## 流程控制

**继续 / 不再行动**

- 确认选择完成当前工作
- 接受输出原样或进入下一步
- 准备继续，无需额外启发
