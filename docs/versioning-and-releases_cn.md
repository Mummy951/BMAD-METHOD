# 如何发布新版本

## 自动发布（推荐）

发布新版本的最简单方法是通过**自动语义发布**。只需使用正确的消息格式提交并推送，其他一切都会自动发生。

### 提交消息格式

使用这些前缀来控制发生哪种类型的发布：

```bash
fix: 解决 CLI 参数解析错误      # → 补丁发布 (4.1.0 → 4.1.1)
feat: 添加新的代理编排模式     # → 次要发布 (4.1.0 → 4.2.0)
feat!: 重新设计 CLI 界面              # → 主要发布 (4.1.0 → 5.0.0)
```

### 自动发生的事情

当您推送带有 `fix:` 或 `feat:` 的提交时，GitHub Actions 将会：

1. ✅ 分析您的提交消息
2. ✅ 更新 `package.json` 中的版本
3. ✅ 生成变更日志
4. ✅ 创建 git 标签
5. ✅ **自动发布到 NPM**
6. ✅ 创建带有说明的 GitHub 发布

### 您的简单工作流程

```bash
# 进行您的更改
git add .
git commit -m "feat: 添加团队协作模式"
git push

# 就是这样！发布自动进行 🎉
# 用户现在可以运行：npx bmad-method（并获取新版本）
```

### 不触发发布的提交

这些提交类型不会创建发布（用于维护）：

```bash
chore: 更新依赖项     # 不发布
docs: 修复自述文件中的拼写错误      # 不发布
style: 格式化代码            # 不发布
test: 添加单元测试          # 不发布
```

### 测试您的设置

```bash
npm run release:test    # 可以在本地安全运行 - 测试配置
```

## 手动发布方法（仅限例外情况）

⚠️ 仅在您需要绕过自动系统时才使用这些方法

### 快速手动版本提升

```bash
npm run version:patch   # 4.1.0 → 4.1.1 (错误修复)
npm run version:minor   # 4.1.0 → 4.2.0 (新功能)
npm run version:major   # 4.1.0 → 5.0.0 (破坏性更改)

# 然后手动发布：
npm publish
git push && git push --tags
```

### 手动 GitHub Actions 触发

如果需要，您也可以通过 GitHub Actions 工作流调度手动触发发布。
